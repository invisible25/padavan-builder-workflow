# netloss — измерение потерь пакетов без доверия к ICMP (Windows 11)

## Зачем это нужно

Если провайдер подделывает (или искусственно "чинит") ICMP echo-ответы на
границе сети, обычный `ping` начинает всегда показывать 0% потерь — даже
если реальный трафик деградирует. При этом реальные потери видны, например,
внутри VPN-туннеля (OpenVPN, WireGuard — не важно), потому что там провайдер
уже не может незаметно подменить пакеты без разрыва протокола.

`netloss.py` вообще не использует ICMP. Он измеряет реальную доставку
пакетов по TCP и UDP — тем способом, который провайдер не может подделать,
не разорвав при этом настоящее соединение.

Инструмент рассчитан на **Windows 11**. Никаких сторонних библиотек не
нужно (только стандартная библиотека Python), права администратора не
требуются.

---

## Установка на Windows 11

**Шаг 1. Установить Python** (если ещё не установлен).

Проверьте, установлен ли Python — откройте **PowerShell** (правой кнопкой по
кнопке «Пуск» → *Терминал* или *Windows PowerShell*) и введите:

```powershell
python --version
```

Если видите `Python 3.8` или новее — всё готово, переходите к шагу 2.
Если пишет, что команда не найдена — установите Python:

- Простой способ: в PowerShell выполнить `winget install Python.Python.3.12`
- Или скачать установщик с https://www.python.org/downloads/ и при установке
  **обязательно поставить галочку «Add python.exe to PATH»**.

После установки закройте и заново откройте PowerShell, проверьте
`python --version` ещё раз.

**Шаг 2. Скачать `netloss.py`.**

Достаточно одного файла — `tools/netloss/netloss.py` из этого репозитория.
Положите его в удобную папку, например `C:\netloss\`.

**Шаг 3. Перейти в папку с файлом в PowerShell:**

```powershell
cd C:\netloss
```

Всё, можно запускать.

## ВАЖНО: запускать при включённом VPN

Потери у вас появляются только когда подключён VPN. Значит и замерять нужно
**при включённом VPN** — тогда пробы пойдут через туннель и покажут те же
потери, что вы наблюдаете. Если запустить без VPN — потерь не будет, это
нормально.

---

## ВАЖНО: почему обычный TCP может показывать «OK» при реальных потерях

TCP — надёжный протокол: если пакет установки соединения (SYN) теряется,
операционная система **сама молча переотправляет** его. Поэтому обычная
TCP-проба к IP с потерями всё равно завершается успехом и показывает `OK` —
потери оказываются скрыты. Именно поэтому IP «под лосами» может показывать
`OK`.

Есть два способа это обойти (см. ниже): **`tcp --single-shot`** (короткий
тайм-аут, одна проба = один SYN) и режим **`dns`** (UDP, где переотправки
вообще нет). UDP-способы честнее показывают реальные потери.

---

## Режим 1: `tcp` — проверка любого IP:порт (сервер НЕ нужен)

Работает с одного вашего компьютера, без серверов. Подходит для тех же IP,
которые вы раньше пинговали. Инструмент выполняет TCP-подключение по
расписанию и различает:

- `OK` — подключение установлено, реальная задержка (RTT) записана
- `TIMEOUT` — ответа нет вообще (ни SYN-ACK, ни RST) — **это и есть потеря**
- `REFUSED` — хост ответил отказом (порт закрыт, но хост доступен) — **это
  не потеря пакетов**, а просто закрытый порт; считается отдельно
- `UNREACHABLE` / `ERROR:...` — сеть/хост недоступны — считается потерей

Обычный запуск (порт должен быть открыт на целевом IP — у сайтов обычно 443):

```powershell
python netloss.py tcp --host 45.133.192.230 --port 443 --interval 1 --log loss.csv
```

**Если IP с потерями всё равно показывает `OK`** — добавьте `--single-shot`.
В этом режиме тайм-аут короткий (0.5с), и переотправка SYN уже не успевает
«спасти» пробу, поэтому реальные потери становятся видны:

```powershell
python netloss.py tcp --host 45.133.192.230 --port 443 --single-shot --interval 1 --log loss.csv
```

> Примечание: в режиме `--single-shot` процент потерь получается выше, чем
> «односторонние» потери канала, потому что для `OK` нужно, чтобы дошёл и
> запрос, и ответ с первой попытки (как у обычного ping). Это нормально —
> главное, что потери на плохом IP видны, а на хорошем их нет.

Остановить — **Ctrl+C**. В конце печатается итоговая сводка.

---

## Режим 2: `dns` — UDP-пробы к публичному резолверу (сервер НЕ нужен)

Самый надёжный способ измерить реальные потери **без своего сервера**.
Инструмент шлёт UDP DNS-запросы на публичный резолвер (8.8.8.8 или 1.1.1.1)
и считает, на сколько запросов пришёл ответ. UDP не переотправляет пакеты,
поэтому потери видны честно. При включённом VPN запросы идут через туннель —
провайдер их не подменит, и вы увидите реальные потери туннеля.

```powershell
python netloss.py dns --host 8.8.8.8 --interval 0.2 --log loss.csv
```

Статусы: `OK` — ответ пришёл; `LOST` — ответа не было за `--timeout` (по
умолчанию 1с); `LATE` — ответ пришёл, но с опозданием (переупорядочивание, не
потеря).

> Этот режим измеряет потери на **пути через туннель**, а не до конкретного
> IP назначения. Если ваши потери создаёт провайдер на VPN-трафике (обычный
> случай), это именно то, что нужно. Для конкретного IP (например
> 45.133.192.230) используйте `tcp --single-shot`.

---

## Режим 3: `udp-client` / `udp-server` — эталонное измерение (нужен свой сервер)

Это наиболее точный аналог того, что вы уже наблюдаете внутри VPN-туннеля:
клиент шлёт пронумерованные UDP-пакеты с меткой времени, сервер сразу
отправляет их обратно, клиент считает, какие вернулись, а какие — нет.
Провайдер не может подделать эту доставку.

Для этого режима нужен маленький сервер-эхо на узле, который вы
контролируете — например, ваш VPS или сам VPN-сервер. Сервер — это тот же
файл `netloss.py` (Python есть и под Linux, и под Windows).

**На сервере (ваш VPS / VPN-сервер), запустить один раз и оставить работать:**

```
python netloss.py udp-server --port 5005
```

> Если на сервере есть фаервол — откройте UDP-порт 5005. На своём VPS это
> обычно `sudo ufw allow 5005/udp` либо соответствующее правило в панели.

**На своём компьютере (Windows 11):**

```powershell
python netloss.py udp-client --host vpn.example.com --port 5005 --interval 0.2 --log loss.csv
```

Статусы в выводе:
- `OK` — пакет дошёл и вернулся, RTT записан
- `LOST` — пакет не вернулся за `--timeout` секунд (по умолчанию 1с) — потеря
- `LATE` — пакет всё-таки вернулся, но уже после того, как был засчитан как
  `LOST` — это переупорядочивание/большая задержка, а не потеря, поэтому
  считается отдельно

> Если у вас нет отдельного сервера — используйте **Режим 2 (dns)** или
> **Режим 1 (tcp --single-shot)**, они не требуют ничего, кроме вашего
> Windows-компьютера.

### Какой режим выбрать

- Нужно проверить **конкретный IP** (например 45.133.192.230) без сервера →
  `tcp --single-shot`.
- Нужно измерить **реальные потери туннеля** без сервера → `dns` (к 8.8.8.8).
- Есть **свой VPS/сервер** и нужен самый точный замер → `udp-server` + `udp-client`.

## Логи в реальном времени

Инструмент выводит данные **сразу, в реальном времени**:

- **В консоли** — по строке на каждый пакет/пробу, плюс сводка по «окну»
  (по умолчанию каждые 20 проб или 10 секунд) с процентом потерь, средним RTT
  и джиттером.
- **В CSV-файле** (`--log`) — каждая строка записывается и сбрасывается на
  диск сразу же, так что файл наполняется в реальном времени.

Чтобы **следить за логом в реальном времени в отдельном окне** PowerShell:

```powershell
Get-Content .\loss.csv -Wait -Tail 20
```

CSV-файл можно открыть в Excel для построения графиков — колонки
`timestamp,seq,rtt_ms,status`. Файл открывается на дозапись, старые данные
не стираются.

## Примеры команд

```powershell
:: Проверить конкретный IP с потерями (при включённом VPN)
python netloss.py tcp --host 45.133.192.230 --port 443 --single-shot --interval 1 --log ip_loss.csv

:: Реальные потери туннеля через DNS к публичному резолверу
python netloss.py dns --host 8.8.8.8 --interval 0.2 --log tunnel_loss.csv

:: Самый точный замер до своего сервера, 5 пакетов/сек, 10 минут
python netloss.py udp-client --host vpn.example.com --port 5005 --interval 0.2 --duration 600 --log vpn_loss.csv
```

Полный список параметров любой команды:

```powershell
python netloss.py tcp --help
python netloss.py dns --help
python netloss.py udp-client --help
```

Остановить любой режим — **Ctrl+C**: инструмент напечатает итоговую сводку и
корректно закроет лог-файл.

---

## Известные ограничения

- Ротация лог-файлов не реализована — для нового запуска указывайте новое
  имя файла через `--log`, если не хотите смешивать данные разных сессий.
- Нет автоматических уведомлений или переключения VPN-сервера при
  превышении порога потерь — только измерение и логирование.

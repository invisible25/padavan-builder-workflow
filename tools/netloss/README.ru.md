# netloss — измерение потерь пакетов без доверия к ICMP

## Зачем это нужно

Если провайдер подделывает (или искусственно "чинит") ICMP echo-ответы на
границе сети, обычный `ping` начинает всегда показывать 0% потерь — даже
если реальный трафик деградирует. При этом реальные потери видны, например,
внутри VPN-туннеля (OpenVPN, WireGuard — не важно), потому что там провайдер
уже не может незаметно подменить пакеты без разрыва протокола.

`netloss.py` вообще не использует ICMP. Он измеряет реальную доставку
пакетов по TCP и UDP — тем способом, который провайдер не может подделать,
не разорвав при этом настоящее соединение.

Требования: Python 3.8+ на Windows, никаких дополнительных библиотек не
нужно (используется только стандартная библиотека), права администратора не
требуются.

## Два режима измерения

### 1. `tcp` — проверка произвольного IP:порт (сервер не нужен)

Подходит для тех же IP-адресов, которые вы раньше пинговали. Инструмент
выполняет полное TCP-подключение (`connect()`) по расписанию и различает:

- `OK` — подключение установлено, реальная задержка (RTT) записана
- `TIMEOUT` — ответа нет вообще (ни SYN-ACK, ни RST) — **это и есть потеря**,
  характерный признак блокировки/чёрной дыры на маршруте
- `REFUSED` — хост ответил отказом (порт закрыт, но хост доступен) — **это
  не потеря пакетов**, а просто закрытый порт; считается отдельно, чтобы не
  путать с реальными потерями
- `UNREACHABLE` / `ERROR:...` — сеть/хост недоступны — считается потерей

Пример:
```
python netloss.py tcp --host 1.2.3.4 --port 443 --interval 1 --log loss.csv
```

### 2. `udp-client` / `udp-server` — эталонное измерение (рекомендуется)

Это наиболее точный аналог того, что вы уже наблюдаете внутри VPN-туннеля:
клиент отправляет пронумерованные UDP-пакеты с меткой времени, сервер сразу
отправляет их обратно, клиент засекает, какие вернулись, а какие — нет.
Провайдер не может подделать эту доставку, не доставив (или не потеряв)
настоящий пакет в обе стороны.

Требует небольшого сервера-эхо, запущенного на узле, который вы
контролируете (например, ваш VPS или сам VPN-сервер).

На сервере (VPS/VPN-сервер):
```
python netloss.py udp-server --port 5005
```

На своей машине (Windows):
```
python netloss.py udp-client --host vpn.example.com --port 5005 --interval 0.2 --log loss.csv
```

Статусы в выводе:
- `OK` — пакет дошёл и вернулся, RTT записан
- `LOST` — пакет не вернулся за `--timeout` секунд (по умолчанию 1с) — потеря
- `LATE` — пакет всё-таки вернулся, но уже после того, как был засчитан как
  `LOST` — это переупорядочивание/большая задержка, а не настоящая потеря,
  поэтому считается отдельно

## Формат лога (CSV)

Обе команды пишут строки `timestamp,seq,rtt_ms,status` в файл, указанный
через `--log` (или в автоматически сгенерированное имя, если `--log` не
задан). Файл открывается на дозапись — старые данные не стираются.

В консоль дополнительно печатается:
- строка по каждому пакету/пробе;
- сводка по "окну" (по умолчанию каждые 20 проб или 10 секунд, что наступит
  раньше): процент потерь, средний RTT, джиттер, разбивка по типам ошибок;
- итоговая сводка по всему запуску при завершении (Ctrl+C или по достижении
  `--count`/`--duration`).

## Примеры команд

```
:: TCP-проверка произвольного IP каждую секунду, лог в файл
python netloss.py tcp --host 8.8.8.8 --port 443 --interval 1 --log dns_check.csv

:: Сервер-эхо на VPS (запускать один раз, оставить работать)
python netloss.py udp-server --port 5005

:: Клиент — измерение потерь до VPN-сервера, 5 пакетов в секунду, 10 минут
python netloss.py udp-client --host vpn.example.com --port 5005 --interval 0.2 --duration 600 --log vpn_loss.csv
```

Остановить любой режим — Ctrl+C: инструмент напечатает итоговую сводку и
корректно закроет лог-файл.

## Известные ограничения

- Ротация лог-файлов не реализована — для нового запуска указывайте новое
  имя файла через `--log`, если не хотите смешивать данные разных сессий.
- Нет автоматических уведомлений или переключения VPN-сервера при
  превышении порога потерь — только измерение и логирование.
- Флаг `--drop-rate` у `udp-client` — это **инструмент самопроверки**
  (искусственно "теряет" часть пакетов на стороне клиента, чтобы убедиться,
  что подсчёт потерь работает правильно), а не параметр для реальных
  измерений сети.
